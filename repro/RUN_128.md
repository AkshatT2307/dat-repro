# Runnable 128x128 experiments — fixed epochs

This supersedes the earlier compact fixed-10,000-step instructions. It is a
compute-reduced adaptation of IDR, not an exact reproduction of paper tables.
Existing 50k-step jobs and their output folders have not been stopped/overwritten.

## Run after the current GPU job finishes

```bash
cd repro
# All four models, sequentially: ImageNet IDR/supervised, then Marmousi2 IDR/supervised.
bash run_epoch128.sh all 256 20
```

Or run each experiment separately:

```bash
bash run_epoch128.sh imagenet 256 20
bash run_epoch128.sh marmousi2 256 20
```

Arguments are DATASET, BATCH, EPOCHS. Replace 256 with 128 or 64 if needed.
A short GPU memory preflight runs before training; no automatic batch changes.
Batch 256 has not been GPU-tested alongside the existing job. Failed preflight
stops safely and asks for more free memory or a smaller batch. No other GPU
process is stopped by these scripts.

Each method starts from scratch. Rerunning the SAME command automatically resumes
its own checkpoint, or evaluates if training already completed. Changing batch
uses a different output directory and starts a new run; do not mix protocols.

## What is fixed

Training runs for **up to 20 epochs**, with validation after every epoch.
Early stopping uses clean-reference L1 loss, patience 5 epochs and minimum
improvement 1e-5. Any new lowest loss saves the best checkpoint; improvements
smaller than the threshold do not reset patience. Both methods use identical
validation images and fixed corruptions. Each method can stop at a different
epoch. Twenty epochs is a budget ceiling, not a guarantee of convergence.

ImageNet uses 49,000 training images per epoch, retaining the final partial batch:

| Batch | Updates/epoch | Maximum updates | Maximum image presentations |
|---:|---:|---:|---:|
| 64 | 766 | 15,320 | 980,000 |
| 128 | 383 | 7,660 | 980,000 |
| 256 | 192 | 3,840 | 980,000 |

Adam starts at 3e-4; halve LR at ceil(50%) and ceil(80%) of the maximum update
budget. ImageNet batch 256 milestones are 1,920 and 3,072. Marmousi2 retains
50,000 random patch draws per epoch: 196 updates/epoch at batch 256, at most
3,920 updates, milestones 1,960 and 3,136. LR is not multiplied by batch size.
Fast IDR updates its frozen target network at the start of each epoch after the
first. Increasing batch size preserves sample presentations per completed epoch,
but changes the number of optimizer updates and can change convergence and the
early-stop epoch. Runtime is measured live.

Optional stopping settings (keep the same on resume):

```bash
PATIENCE=5 MIN_DELTA=0.00001 bash run_epoch128.sh imagenet 256 20
```

## ImageNet

The downloaded ImageNet validation source contains 50,000 images. A fixed random
split (seed 2026) holds out 1,000 images and trains on the other 49,000. No files
are moved. The manifest is data/imagenet_split.json; each run records its actual
training and validation filenames and split fingerprint. Both methods use the
same split. Take a clean
256x256 crop, area-downsample to 128x128, then add independent Gaussian noise,
sigma uniform [0,50]/255. RGB U-Net, original Fast IDR target logic, and a matched
supervised U-Net. Training loader matches upstream preprocessing otherwise.

For validation, use a fixed center crop, area-downsample to 128x128, and add
fixed Gaussian noise at sigma 25 and 50. Average float L1 loss equally across
the two noise levels; no clipping or quantization. The held-out clean images
are used for model selection, including Fast IDR, but never for gradient updates.
This makes the modified protocol clean-reference-guided model selection.

**Kodak and BSDS are never used for early stopping or checkpoint selection.**
Final evaluation of the best checkpoint uses the original full-resolution Kodak (24) and BSDS300 (300)
images at sigma 25 and 50, with identical seeded corruptions for both models.
Reported metrics are PSNR/SSIM. Smaller training patches do not require resizing
full-resolution inference images.

## Marmousi2

The selected NMOstack_time section is downloaded and prepared at data/marmousi2.
Verified archive SHA-256:
`b6fe8d10ce6a6dfadf203a8d0e1a040ce9f2c6cb52c1366193d35113d61797fe`.
Original source/mirror URLs, archive member, header info and section checksum are
in metadata.json. Original LICENSE and README are retained. CC BY 4.0; cite
Martin, Wiley and Marfurt (2006), Marmousi2: An elastic upgrade for Marmousi.

To recreate on a fresh checkout:

```bash
.venv/bin/python prepare_seismic.py
```

- Real prepared section: 1,001 time samples x 2,721 traces; sample interval 4 ms.
- Spatial trace splits (Python half-open intervals): training [0,1632), validation
  [1760,2176), test [2304,2721). Each boundary has a 128-trace unused buffer.
- Native 128x128 patches. Signed float32 amplitudes, no uint8 conversion, no
  clipping, no RGB offset. Normalize with ONLY training-region RMS; inverse
  scale is retained for metrics.
- An epoch is explicitly defined as 50,000 random training patch draws (not
  50,000 distinct field records). This is separate from ImageNet's 49,000-image training budget.
  Patches overlap within training, but never cross split boundaries.
- One-channel U-Net. Known added Gaussian noise std is sampled uniformly from
  [0,0.5] in train-RMS-normalized units. Same noise model for both methods.
- Fast IDR uses noisy/refined targets. Supervised uses reference section patches.
- The validation trace region supplies fixed-noise L1 loss at each epoch for
  early stopping; the test trace region is never used for model selection.
- After training, evaluate the best checkpoint on both held-out splits at sigma 0.1/0.2/0.4, using 21
  nonoverlapping patches per split and identical fixed noise across methods.
- Metrics: input/output SNR, SNR gain, normalized/original-amplitude RMSE,
  waveform correlation and removed-residual/reference correlation. Exclude
  zero-signal patches from SNR averaging; preserve their RMSE measurements.
- Save per-tile CSVs, JSON summaries, numerical reference/noisy/denoised/residual
  NPZ examples and fixed-display-scale PNG previews. PNG clipping is for display
  only, never training or metrics.

This is removal of deliberately ADDED noise relative to a processed synthetic
reference. It does not establish recovery of true clean field seismic, or
cross-survey generalization. One section is a controlled pilot.

## Outputs, logs and resume

`runs/epoch128/{imagenet,marmousi2}/{idr,supervised}/b256_e20/` contains:

- config.json and training/validation manifests (ImageNet).
- metrics.jsonl (every optimizer step), validation.jsonl (every epoch), console.log.
- latest.pt (full resumable state) and weights.pth (latest model).
- best.pt (full state at lowest validation loss) and best_weights.pth.
- training_summary.json (best epoch/loss, completed epochs/steps, stopping state).
- Final evaluation outputs from best_weights.pth; seismic also has validation reports.

Save latest checkpoints every 1,000 updates, at the final update, and after each
validation epoch. Resume restores optimizer, LR scheduler, Fast IDR teacher,
RNG state, split identity and patience counters. Incompatible old checkpoints
are rejected; use a fresh output directory for the changed protocol.
Complete pipeline output is also in logs/.
Combined comparisons: `runs/epoch128/DATASET/comparison_b256_e20/results.csv`.

No network/GPU work is needed for a plan:

```bash
.venv/bin/python gaussian.py train --profile compact --dataset imagenet --method idr --data data/imagenet_val --batch 256 --epochs 20 --validate --dry-run
.venv/bin/python gaussian.py train --profile compact --dataset marmousi2 --method idr --data data/marmousi2 --batch 256 --epochs 20 --validate --dry-run
```

Direct single-method commands accept --resume. For custom seismic exposure,
--samples-per-epoch changes random patch draws and scales the update count;
use the same value for both methods. Never change these settings on resume.

## Active overnight supervision

The current launch is `bash run_epoch128.sh all 192 20` in tmux session `idr128`.
A detached monitor process runs monitor_overnight.py in the same training pane and and updates OVERNIGHT_STATUS.md every
30 seconds. That report records live progress, validation losses, all adjustment
decisions, and selected paired configurations. It continues after the chat ends.

The monitor lets the initial pipeline finish, then checks each dataset. An
incomplete pipeline gets at most one recovery attempt (resume existing settings,
or fresh batch 128 after a numerical/memory failure). A completed pair gets one
quality retry only if a model fails to reduce expected noisy-input validation L1
by 10%, or Fast IDR L1 exceeds 1.5 times supervised L1. That retry trains both
methods at batch 128, up to 30 epochs, in separate folders. It selects the paired
configuration with lower mean validation loss, preserving every original result.
These thresholds are operational failure checks, not paper-result guarantees.
Generalization/test metrics never influence these decisions. Healthy initial
runs retain batch 192 and the 20-epoch ceiling.

Events: logs/overnight_events.jsonl. Monitor console: logs/overnight_monitor.log.
Stop future automatic actions with `kill -INT $(cat logs/overnight_monitor.pid)`; this
does not stop an already running training pipeline. No unrelated GPU processes
are terminated. Recovery is bounded; unresolved failures are reported for review.

## Five-epoch checkpoint continuations

Run `.venv/bin/python -u run_continuations.py` to continue each of the six trained
models for up to five more completed epochs. Outputs are separate under
runs/continuation5; progress is in CONTINUATION_STATUS.md. The queue retains each
model's batch size, data split, optimizer, teacher and original absolute learning
rate milestones. All six source checkpoints have passed those milestones, so
continuations retain LR 7.5e-5 without resetting or replaying decays.

Continuation starts from latest.pt, retains the previous best checkpoint/loss,
and explicitly resets the no-improvement counter to grant fresh patience.
The four 20-epoch runs have a new limit of 25. Seismic batch-128 IDR resumes
from epoch 24 to at most 29; supervised resumes from 25 to at most 30.
Generalization evaluation uses the best checkpoint across parent and continuation.
Validation logs in the new folder contain only additional epochs. Original runs
and their evaluation files remain untouched. Rerunning the queue resumes its
prepared runs. This is a new experimental branch, not an exact uninterrupted
run with the original early-stopping history.

A CPU smoke continuation verified preserved teacher/optimizer/scheduler loading,
additional step accounting, validation and retention of an earlier best model.
